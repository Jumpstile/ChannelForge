## 5. M3U parse, identity, and exact bytes


An M3U occurrence begins at one #EXTINF line and its immediately following stream URL line. The parser retains source ordinal only as non-semantic provenance; canonical ordering never uses parser/input order. Attribute names are ASCII case-insensitive for parsing only. The raw attribute value between the matching quotes is preserved exactly. The recognized fields are tvg-id, tvg-name, tvg-logo, tvg-chno, group-title, and the display name after the first comma. StreamUrl is the complete URL line with its terminating CR/LF removed; its exact value is retained for output but is never stored in accepted state, decisions, review evidence, or diagnostics.

RawM3UOccurrence property order is Version, LogicalSourceId, RawTvgIdPresence, RawTvgId, TvgName, DisplayName, GroupTitle, Logo, ChannelNumber, StreamUrl, SourceLocalOrdinal, RawM3UOccurrenceDigest. Presence is Present or Missing. Missing is null in RawTvgId and is distinct from Present with an empty string or whitespace-only string. RawM3UOccurrenceDigest omits itself and hashes all other properties in raw-m3u-occurrence/v2. No field is trimmed, normalized, or case-folded for guide binding.

Lineup-history-v1 uses an explicitly versioned key: if RawTvgId is Present, HistoryKey is the Unicode case-folded, Unicode-normalized-form-C, surrounding-ASCII-whitespace-trimmed value; if Missing, HistoryKey is null. This normalization is never used for guide binding. A raw identity collision means two or more distinct RawTvgId values map to one HistoryKey. Every entry in a collision receives a unique EntryId:

EntryId = H(entry-id/v2, { Version, LogicalSourceId, SourceLocalOrdinal, RawM3UOccurrenceDigest })

SourceLocalOrdinal is zero-based and is assigned after canonical sorting of all raw occurrences of one LogicalSourceId by the tuple (RawM3UOccurrenceDigest, RawTvgIdPresence rank, RawTvgId or empty, TvgName or empty, DisplayName or empty, GroupTitle or empty, Logo or empty, ChannelNumber or empty, StreamUrl). Equal complete raw occurrences have identical digests and are exact duplicates; their multiplicity is stored in DuplicateCount and only the representative with the lowest canonical tuple is retained. Input order never selects a representative.

M3UIdentityCollisions has property order Version, HistoryKey, CollisionKind, RawIdentityDigests, EntryIds, MissingIdentityCount, IdentityPopulation, CollisionEvidenceDigest. CollisionKind is MissingOnly, PresentCollision, MixedMissingAndPresent, or None. RawIdentityDigests and EntryIds are unique lowercase 64-hex values sorted ascending by ordinal string bytes. Duplicate members are rejected during canonical construction; they are never silently repeated. IdentityPopulation is the total number of raw occurrences in the group, including missing and non-missing occurrences. MissingIdentityCount is the number with RawTvgIdPresence=Missing. The invariant is IdentityPopulation = MissingIdentityCount + number of non-missing raw occurrences. A collision group is emitted for every HistoryKey with population greater than one and for every missing-ID population greater than zero. Any group with multiple raw records participating in the same exact guide identity is ReviewNeeded and cannot be ExactBound, including when normal lineup dedup would keep one survivor. This is the PR #100 pre-dedup evidence contract.

The canonical candidate M3U bytes use UTF-8 without BOM, LF line endings, and exactly:

#EXTM3U
one record per retained entry in EntryId ascending order:
#EXTINF:-1[, attributes],DisplayName
StreamUrl

Attribute order is tvg-id, tvg-name, tvg-logo, tvg-chno, group-title. An absent attribute is omitted. A present value is emitted inside double quotes; reverse solidus and double quote are escaped with a reverse solidus, and CR, LF, and NUL are rejected. The display name is emitted after the first comma; the same three characters are escaped as XML-independent M3U text by replacing CR/LF/NUL with a validation error, never by lossy substitution. The exact StreamUrl is emitted as the second line. The final file ends with LF. The candidate-m3u/v2 hash is over these exact bytes. URLs are present only in this output artifact and in the stream fingerprint input; they are not persisted in state, decisions, or review reports.

## 6. XMLTV parse, identity, and exact bytes

One RawXMLTVChannelOccurrence is created for every <channel> element in source selection order before canonical ordering. One RawProgrammeOccurrence is created for every <programme> element. Source order is provenance only.

RawXMLTVChannelOccurrence property order is Version, LogicalSourceId, StructuralOccurrenceOrdinal, RawChannelIdPresence, RawChannelId, DisplayNameNodes, IconNodes, RawChannelExtensions, RawXMLTVOccurrenceDigest. RawProgrammeOccurrence property order is Version, LogicalSourceId, StructuralOccurrenceOrdinal, RawProgrammeChannelIdPresence, RawProgrammeChannelId, StartRaw, StopRaw, TitleNodes, SubTitleNodes, DescNodes, CategoryNodes, EpisodeNumbers, Rating, StarRating, PreviouslyShown, Premiere, LastChance, Credits, Date, IconNodes, RawProgrammeExtensions, RawProgrammeDigest. All values are exact XML lexical values after only XML parser entity decoding; no whitespace trim or Unicode normalization is applied to IDs or timestamp strings. Missing, empty, and whitespace-only IDs are distinct: Missing has Presence=Missing and Value=null; empty has Presence=Present and Value=""; whitespace-only has Presence=Present and the exact whitespace string.

StructuralOccurrenceOrdinal is zero-based within the complete population of raw occurrences of the same LogicalSourceId and element kind, assigned by canonical sort, not parser order. Channel sort tuple is (RawChannelIdPresence rank, RawChannelId or empty, canonical display-node bytes, canonical icon-node bytes, canonical extension bytes, RawXMLTVOccurrenceDigest). Programme sort tuple is (RawProgrammeChannelIdPresence rank, RawProgrammeChannelId or empty, StartRaw or empty, StopRaw or empty, canonical title/subtitle/desc/category/episode/extension bytes, RawProgrammeDigest). A complete tie has identical raw digest and is represented with DuplicateCount; otherwise the digest is the final tie-breaker. No input permutation changes the ordinal.

GuideCandidateIdRecord has property order Presence, Value, OccurrenceCount, MissingIdentityCount, OccurrenceDigests, OccurrenceOrdinals. Values are null only for Missing; Present empty and Present whitespace remain strings. OccurrenceCount includes every occurrence in the group. MissingIdentityCount counts only Presence=Missing; OccurrenceCount = MissingIdentityCount + the count of Present occurrences. OccurrenceDigests and OccurrenceOrdinals are unique, ascending by the canonical occurrence tuple; an invalid duplicate ordinal or digest fails closed.

For each raw channel occurrence, the BindingKey is H(binding-key/v2, { LogicalSourceId, StructuralOccurrenceOrdinal, RawChannelIdPresence, RawChannelId }). It is unique even for XMLTV-only occurrences. A BindingRecord is created for every M3U EntryId and every XMLTV-only BindingKey. BindingRecord property order is Version, BindingId, BindingKind, EntryId, BindingKey, M3URawIdPresence, M3URawId, XMLTVIdPresence, XMLTVId, CandidateChannelOccurrenceOrdinals, Status, ReasonCode, CollisionEvidence, BindingRecordDigest. BindingId is H(binding-record/v2, the record without BindingId or BindingRecordDigest). BindingKind is M3U, XMLTVOnly, or RejectedXMLTV. XMLTV-only records have EntryId=null, XMLTV fields required, and a unique BindingKey; M3U records have EntryId required. A rejected guide candidate remains represented as XMLTVOnly or RejectedXMLTV according to the source parser result and remains in the accepted XMLTV artifact; rejection changes only binding status and never manufactures ExactBound.

Guide binding is exact ordinal equality of raw M3U tvg-id and raw XMLTV channel ID. No trim, case fold, Unicode normalization, whitespace removal, or SafeText conversion is used. ExactBound requires one M3U raw record, one XMLTV channel occurrence, both IDs Present, both raw strings byte-for-byte equal as Unicode scalar sequences, no M3U identity collision, no XMLTV duplicate/collision, and sufficient source-set evidence. Missing, empty, whitespace-only, case-only, confusable, duplicate, or collision cases are Unbound or ReviewNeeded with deterministic ReasonCode; none is ExactBound. GuideCandidateEvidenceDigest excludes OccurrenceIdentityDigest, SafeDisplayFingerprint, and SafeGroupFingerprint. GuideCandidateEvidenceInput contains only BindingKey, raw ID presence/value, occurrence ordinal, source ID, and candidate cardinality evidence.

XMLTV channel output contains every selected raw channel occurrence in StructuralOccurrenceOrdinal order, including missing, empty, whitespace-only, duplicate, and rejected occurrences. Programmes are included in StructuralOccurrenceOrdinal order and retain the exact channel ID reference. No XMLTV occurrence is omitted because guide binding was rejected. XMLTVOnly is therefore a valid output status, not a deletion instruction.

The canonical XMLTV bytes are UTF-8 without BOM, LF line endings, and exact declaration:
<?xml version="1.0" encoding="UTF-8"?>
<tv>
...
</tv>
Each element is emitted with no indentation. Attribute order is channel id, programme channel, start, stop, then attributes in parser-schema order defined above. Attribute values escape ampersand, quote, less-than, and greater-than as &amp;, &quot;, &lt;, and &gt;. Text escapes ampersand, less-than, and greater-than. Apostrophe is emitted literally in text and as &apos; in attributes. Empty elements use <x/>. All original field presence is retained; no default attribute is invented. StartRaw and StopRaw are emitted exactly as parsed. If a programme has no stop, stop is omitted. A generated XMLTV artifact is the exact selected source projection, not a formatter-dependent reserialization. candidate-xmltv/v2 hashes these exact bytes.

Programme identity is H(raw-programme/v2, { LogicalSourceId, StructuralOccurrenceOrdinal, raw channel ID, StartRaw, StopRaw, canonical repeated fields }). Exact duplicate programme occurrences have DuplicateCount and one deterministic representative; conflicting same-key programmes are retained as separate occurrences and generate ReviewNeeded. Source-set selection is the sorted unique LogicalSourceIds selected by configuration; competing source values are not merged by fuzzy or parser order.

## 7. Candidate, review, decision, and accepted schemas

BuildIdentity is H(candidate-manifest/v2, a canonical object containing ContractVersion, IdentityRulesVersion, selected LogicalSourceIds, exact input artifact hashes, parser/serializer versions, and the exact guide-binding contract version). It excludes current time, transaction ID, cache state, filesystem identity, and acceptance timestamp. A candidate with identical canonical inputs has one BuildIdentity.

CandidateManifest property order is Version, ContractVersion, BuildIdentity, IdentityRulesVersion, SelectedSources, InputArtifactHashes, Entries, M3UIdentityCollisions, GuideOccurrences, RawProgrammes, BindingRecords, ChangeRecords, ReviewRecords, ArtifactRecords, CandidateManifestHash. It contains no self ArtifactRecord and no filesystem metadata. ArtifactRecord is Role, RelativePath, Status, ByteLength, ContentDomain, ContentHash. RelativePath is a fixed contract path within the candidate namespace and cannot be absolute or reparse-based.

Entry projection property order is EntryId, LogicalSourceId, SourceLocalOrdinal, HistoryKey, HistoryIdentityStatus, RawTvgIdPresence, RawTvgId, TvgName, DisplayName, GroupTitle, Logo, ChannelNumber, StreamFingerprint, PresentationFingerprint, EntryOutputSlice. StreamFingerprint includes exact StreamUrl in stream-fingerprint/v2 and is never exposed in review text; PresentationFingerprint includes only permitted presentation fields (TvgName, DisplayName, GroupTitle, Logo, ChannelNumber). EntryOutputSlice is RelativePath, ByteOffset, ByteLength, EntryContentHash and points into candidate.m3u; it contains no URL.

ChangeRecord property order is ChangeRecordId, Classification, CandidateEntryId, AcceptedEntryId, CandidateEntryProjection, AcceptedEntryProjection, Evidence, ReviewId. CandidateEntryId and AcceptedEntryId use null-first ordering only in sort keys, not as an instruction. Classification precedence is IdentityConflict, ReviewNeeded, Added, Removed, IdentityChanged, StreamAndPresentationChanged, StreamChanged, Renamed, Unchanged. Renamed requires the same unique history key, unchanged stream identity, changed presentation, no collision, same IdentityRulesVersion, and evidence sufficient. A raw ID change is IdentityChanged/ReviewNeeded, never an automatic rename. A case-only or whitespace-only raw ID change may retain a history key but is still reported in raw evidence; it never weakens guide binding. StreamChanged and StreamAndPresentationChanged are distinct; combined changes use the higher-precedence combined classification.

ReviewRecord property order is ReviewId, ReviewCategory, Classification, ReasonCode, CandidateEntryIds, AcceptedEntryIds, CandidateBindingIds, DecisionTypesAllowed, Evidence, ReviewRecordDigest. ReviewId is H(review-id/v2, the record without ReviewId or digest). CandidateEntryIds and AcceptedEntryIds are unique sorted EntryIds; an actionable review is required to have exactly one candidate and exactly one accepted ID unless DecisionTypesAllowed explicitly contains a compound mapping type. v2 defines no compound mapping type, so multi-entry actionable records are invalid and must be split into separate review records. XMLTV-only reviews have CandidateEntryIds=[] and AcceptedEntryIds=[] and a unique BindingKey in Evidence; their ReviewId includes that BindingKey and occurrence ordinal. Evidence arrays are sorted by (EvidenceType rank, Value type rank, canonical value bytes, Ordinal), with Ordinal required and equal to GuideCandidateEvidenceInput.OccurrenceOrdinal for GuideCandidate evidence and null/forbidden for all other evidence types.

DecisionManifest property order is Version, CandidateManifestHash, BuildIdentity, AcceptedParentGenerationManifestHash, IdentityRulesVersion, Decisions, ReviewedDecisionIds, CoveredReviewIds, IncludedCandidateEntryIds, ExcludedCandidateEntryIds, DecisionManifestHash. Decisions are unique and sorted by (DecisionType rank, DecisionId); every DecisionId is H(decision-manifest/v2, the decision without its ID). ReviewedDecisionIds contains unique DecisionIds. CoveredReviewIds contains unique ReviewIds. Every actionable ReviewId occurs exactly once in CoveredReviewIds, and no non-actionable ReviewId occurs. IncludedCandidateEntryIds and ExcludedCandidateEntryIds are unique, disjoint, and their union is exactly all candidate EntryIds; both arrays are sorted ascending EntryId bytes. No decision may cover two incompatible classifications. An acceptance fails if a required decision is missing, duplicated, stale, conflicted, or not allowed by its ReviewRecord.

Decision types and exact predicates:
- AcceptGuideBinding requires one ReviewId, one BindingId, one exact candidate BindingRecord, and exact raw ordinal equality; it is forbidden for collision, duplicate, missing, or ambiguous evidence.
- MapCandidateToAcceptedEntry requires exactly one candidate EntryId and one accepted EntryId, unchanged unique history identity, unchanged IdentityRulesVersion, sufficient evidence, and no collision.
- KeepAcceptedEntry requires exactly one accepted EntryId and an exact old-generation output slice; it cannot be used for a new or changed identity.
- IncludeCandidateEntry requires one candidate EntryId and no unresolved review.
- ExcludeCandidateEntry requires one candidate EntryId and an explicit reason.
All decision IDs, parent hash, candidate hash, covered review IDs, and decision fields must match the current immutable candidate and the accepted parent. A stale BuildIdentity, stale CandidateManifestHash, stale parent hash, changed IdentityRulesVersion, unresolved ReviewNeeded, duplicate coverage, or conflict rejects acceptance.

Accepted projection is deterministic and complete. Start with candidate entries included by decision. For each retained accepted entry, use the exact old generation output slice named by the old AcceptedOutputManifest, never cache or current output inference. For each mapped entry, use the candidate slice. Sort final M3U entries by EntryId and serialize using the M3U contract. Accepted XMLTV is the selected candidate XMLTV projection, including XMLTV-only/rejected occurrences. Guide rejection changes BindingRecord status only. AcceptedState never stores URLs or raw XMLTV. It stores candidate/decision/parent/output hashes and exact accepted IDs only.

AcceptedOutputManifest property order is Version, GenerationSemanticId, AcceptedEntrySlices, AcceptedBindingSlices, AcceptedXMLTVStatus, AcceptedXMLTVHash, OutputM3UHash, OutputXMLTVHash, OutputManifestHash. AcceptedEntrySlices and AcceptedBindingSlices are sorted by their IDs. OutputManifestHash omits itself and hashes all other properties. AcceptedXMLTVStatus is Generated or NotGenerated. Generated requires merged.xml and a non-null lowercase 64-hex AcceptedXMLTVHash equal to OutputXMLTVHash; NotGenerated requires no merged.xml and null AcceptedXMLTVHash and OutputXMLTVHash. AcceptedAtUtc is audit metadata in AcceptedState, RFC3339 UTC with Z, excluded from AcceptedStateHash and all semantic comparison hashes; timestamp differences do not change semantic equality.

GenerationManifest property order is Version, GenerationId, BuildIdentity, CandidateManifestHash, DecisionManifestHash, AcceptedStateHash, AcceptedOutputManifestHash, GenerationManifestHash. GenerationManifestHash omits itself. GenerationId is 32 lowercase hex random bytes generated before staging and is operational only; it is carried by pointer and journal but excluded from semantic hashes. The generation is complete only if all files, referenced hashes, output slices, and schema versions validate.

accepted-lineup.json pointer property order is Version, GenerationId, GenerationManifestHash, AcceptedStateHash, AcceptedOutputManifestHash, PointerHash. PointerHash omits itself and is operational pointer integrity, not a content identity. It is replaced atomically. accepted-lineup.json.previous is the previous complete pointer byte set; no previous file exists on first acceptance.
